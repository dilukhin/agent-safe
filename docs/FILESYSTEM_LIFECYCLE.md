# Жизненный цикл файлов и каталогов

## Назначение

`agent-safe` не является песочницей и не пытается сделать намеренный обход невозможным. Его задача — поставить технические «перила» вокруг опасных операций: сделать намерение явным, ограничить точную цель, проверить результат и оставить журнал, пригодный для последующего разбора.

Для файловой системы это означает, что необратимое удаление допускается, но только после явной классификации объекта как временного.

## Классы ресурсов

Поддерживаются три простых класса:

- `normal` — класс по умолчанию. Окончательное удаление через `fs-cleanup` запрещено;
- `temporary` — объект явно признан расходным. Окончательное удаление разрешено;
- `protected` — объект явно отмечен как требующий сохранения. Окончательное удаление запрещено.

Класс можно назначить существующему файлу или каталогу задним числом. Это сознательная часть модели: `safe` защищает прежде всего от случайной ошибки, а не от агента, который намеренно пытается обойти правила.

## Команды

Назначить класс:

```bash
safe fs-mark ./probe --class temporary --reason "временные данные проверки"
```

Посмотреть фактическое состояние и историю:

```bash
safe fs-status ./probe
```

Окончательно удалить временный объект:

```bash
safe fs-cleanup ./probe --reason "проверка завершена"
```

Для обычного удаления по-прежнему используется обратимый маршрут:

```bash
safe fs-trash ./path --reason "убрать объект обратимо"
```

Если объект был помечен `temporary` до `fs-move` или `fs-trash`, класс отслеживается по журналируемому переходу пути. Поэтому допустим двухступенчатый сценарий:

```text
temporary + present
        ↓ fs-trash
temporary + trash
        ↓ fs-cleanup
deleted + tombstone
```

Уже находящийся в `.agent-safety/trash` конкретный объект также можно явно переклассифицировать в `temporary` и затем очистить окончательно.

## Аудит необратимого удаления

`fs-cleanup` не должен быть бесследным. До физического удаления в append-only журнал записывается `fs.cleanup.intent` со следующими данными:

- `txn_id`;
- точный путь;
- причина;
- класс `temporary`;
- ожидаемое состояние `path_exists=false`;
- краткий снимок объекта до удаления;
- признак `reversibility=irreversible`.

После действия записывается `fs.cleanup` с тем же `txn_id`. Успешная запись является tombstone удалённого объекта и содержит результат проверки отсутствия пути. Для обычного файла снимок включает размер и SHA-256; для каталога — ограниченную статистику по содержимому.

Если операция завершается ошибкой либо путь после неё всё ещё существует, транзакция получает `unexpected`, создаётся `INCIDENT_BLOCKED`, и исходная задача должна остановиться для read-only диагностики и recovery.

## Ограничения

`fs-cleanup` не разрешает удалять:

- объект класса `normal`;
- объект класса `protected`;
- корень файловой системы;
- корень текущего safety-проекта или его родителя;
- служебные данные `.agent-safety`, кроме конкретных объектов внутри `.agent-safety/trash`.

Символьная ссылка удаляется как сама ссылка; `fs-cleanup` не должен следовать по ней к внешней цели.

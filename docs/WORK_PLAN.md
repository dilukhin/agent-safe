- #14 не вводит окончательное удаление и не требует отдельной БД; логическая транзакция не означает атомарность всех файловых перемещений.
- #16 не требует готовности JSON editor или событий надёжности. До первого прогона обязательны serial, точная цель и проверяемое восстановление.
- Контроль разрешений принадлежит opencode_permissions, транспорт — ssh_relay. Их схемы не меняются этим планом.
- Нет автоматического восстановления, слепых повторов или фоновой очистки артефактов.

## Работа с PR и проверки

Перед новым этапом перечитать актуальные master, issues и открытые PR. Один ограниченный результат — один PR; один логический набор — один commit. Не вести две реализации одной части issue одновременно. Изменения публиковать через GitHub Connector; после записи проверять состояние GitHub. Не писать напрямую в master.

Для изменения кода обязательны:

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
PYTHONPATH=src python -m agent_safe --help
PYTHONPATH=src python -m agent_safe opencode-bootstrap --scope project --dry-run
```

Матрица CI: Windows/Ubuntu × Python 3.10/3.14, проверяется по точному head PR. При изменении bootstrap — повторный apply должен быть no-op без новой journal-записи. Для документационного PR проверяются ссылки, соответствие коду и отделение проекта решения от реализованного поведения.

Python stdlib, русские новые сообщения, совместимость журналов, сохранение deny-политики и отсутствие секретов остаются обязательными. Реальные интеграционные проверки учитывать отдельно от имитационных.

После каждого принятого этапа обновлять этот документ и связанную issue. Закрывать задачу после всех критериев либо явного переноса остатка. Согласование архитектуры #15/#25A не означает разрешения менять реальные серверы или устройства.
